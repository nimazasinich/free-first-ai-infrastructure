## Acceptance to date

- **PASS — Dedicated authorization.** Separate client keys were created and restricted to `free/gemini-3.8-flash`. Each Windows credential listed just that model and returned HTTP 403 for the forbidden Pro model. The canary stayed restricted. The launcher reads DPAPI-encrypted secrets under the Windows user account.
- **PASS — Cursor registration, restart and tool transport.** Installed Cursor connected over stdio to the persistent `free-first-gateway` registration, and a fresh isolated Cursor process reconnected after the launcher was made independent of PowerShell module autoloading. A separate Windows test launched the exact registered command, retrieved the approved catalog, and made a real bounded generation through the same key.
- **PASS — Persistent Codex profile and saved Flash migration.** The Windows Codex app server exposed zero legacy tools in the scoped profile. It invoked the real `gateway_models` MCP tool, used its returned model ID to complete a streamed turn, and resumed the same thread in a fresh process. The initial unadapted call reproduced an unsupported namespace error. The Windows-local translator resolved it for the Free-First functions. The backed-up legacy Flash profile was then replaced with the scoped configuration and made a successful real CLI turn.
- **NOT_RUN — Cursor Agent end-to-end.** The installed Cursor extension host's standard language-model tool enumeration exposed none of the registered gateway tools. Agent tool invocation, streaming and tool-result continuation remain separate from the verified stdio workflow. Current Cursor account usage and overage settings were unavailable for a billable-provider test.
- **PARTIAL — Billing.** The VPS path uses one private upstream with direct egress denied and no configured paid provider or fallback. Google's billing FAQ confirms that a paid project key linked in AI Studio can incur charges. The local Cursor membership label confirms the account tier shown by the app. Current Google project/key linkage and billing records, and the Cursor usage ledger and overage settings, were outside the verified evidence. ## Windows installation and rollback

- Run `scripts/provision_client.py codex` and `scripts/provision_client.py cursor` with the local gateway dashboard on the VPS. Run [the Windows installer](../client/Install-FreeFirstWindows.ps1) with the approved public HTTPS `/v1` URL and the existing strict-host-key OpenSSH profile. The installer validates both scoped keys and creates a local backup of changed client configuration.
- The Codex profile is `free-first-gateway`. Launch `Start-FreeFirst.ps1 -Client codex -Codex` from the DPAPI-protected installation directory. The launcher runs the Responses compatibility process for that client on a random Windows loopback port and tears it down when Codex exits. The server only accepts the approved model and its per-process bearer, and it forwards to the fixed HTTPS gateway without redirects.
- Use `-ProfileName gemini-gemini-3-8-flash` with the launcher for the migrated Flash profile. The installer switch `-MigrateApprovedFlashProfile` matches only the approved previous profile and saves it before writing the clean configuration.
- For the native app-server test, run `node tests/windows-codex-app.mjs PATH_TO_INSTALLED_LAUNCHER EMPTY_TEST_DIRECTORY`. The test uses the persistent runtime configuration and runs one MCP result continuation plus one resumed turn after process restart.
- Cursor reads the `free-first-gateway` MCP registration in the user's `.cursor/mcp.json`. The local launcher reads the distinct Cursor credential and offers only catalog and chat. A Cursor MCP registration and a Cursor native model-provider setting serve different purposes.
- If the Windows changes need rollback, restore only the affected Cursor registration and scoped Codex profile from the local client backup. Preserve unrelated updates made after the backup. The VPS administrator can revoke an unused fresh client key through the local dashboard. Preserve the existing canary key and the protected upstream configuration.
